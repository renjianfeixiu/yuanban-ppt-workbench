# 模板内容替换原型

> 这是原始原型的使用记录。GitHub 源码副本的运行方法和环境限制，请先看[仓库首页](../README.md)。

这是一次性可行性原型。问题是：能否在不移动、不重建模板对象的情况下，替换已确认位置的文字与图片，并留下可核对的证据？

先阅读 [产品大纲](</Users/wangdajin/我的文稿/agent task/codex 任务尝试/ppt-template-study/产品大纲.md>)。默认示例是“智慧仓储”的概念方案。保留模板完整 22 页，只替换第二页的 13 个文字位置和 5 张配图。

## 运行

在本机终端执行一条命令，或双击 `run-demo.command`：

```sh
"/Users/wangdajin/我的文稿/agent task/codex 任务尝试/ppt-template-study/demo-prototype/run-demo.command"
```

需要查看拒绝超长文字的交互过程时，在命令末尾加 `--interactive`。每步会打印阶段、判断和验证结果。运行将生成新的版本，不覆盖原模板和已导出的版本。

依赖使用当前 Codex 自带的 Node、Python 和演示文稿工具包，没有安装新的库。换电脑运行需要调整代码顶部的路径。

## 本次验证

1. 核对原模板哈希，找到既有对象 ID。
2. 用明显超长的文字触发容量拒绝，随后采用预先写好的短文案。
3. 只修改文字节点和图片引用，保留字体、字号、强调格式、位置、大小、裁切、母版和背景。
4. 核对全部原始文件部件：只允许第二页 XML 与其图片关系文件变化，新增 5 个媒体部件。
5. 检查包完整性、页面尺寸及对象结构，尝试全套图表校验，再渲染全部页面。
6. 查看第二页前后对照，并使用 **wpsoffice** 进行人工视觉核对。

配图均为概念示意，图片来源和提示词保存在 `assets/素材说明.json`。所有正文仍是可编辑文字；图片可以在 WPS 中替换。

## 边界

文字槽位和文案由本次人工编排，图片由本次预先生成。这个原型没有实现任意新题目的自动写作、通用模板识别和自动审美打分。容量使用近似估算，不能代替实际字体渲染。源文件已有字体缺失及第 18 页图表缓存问题，不能把第二页验证成功说成完整 22 页成品已通过验收。

核心逻辑在 `demo-core.mjs`，命令行适配与验证在 `run-demo.mjs`。原型回答问题后应删除或把经过验证的逻辑迁入正式实现。
